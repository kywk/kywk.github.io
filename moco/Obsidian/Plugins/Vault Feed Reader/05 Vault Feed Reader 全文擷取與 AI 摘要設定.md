# Vault Feed Reader 全文擷取與 AI 摘要設定

Vault Feed Reader 可以在 Markdown 筆記上擷取原文、產生 AI 摘要與主題標籤，適用於 Feed 保存筆記，也可配合 Web Clipper 或已有來源網址的筆記。

最常用的流程是：先保存文章，開啟筆記，再執行「抓取全文並摘要」。若已經剪藏完整正文，可設定全文辨識規則後直接摘要，避免重新抓網頁。

## 先選擇要做的事

在目前的 Markdown 筆記開啟命令面板（macOS 預設 `Cmd+P`），搜尋以下命令。請先離開閱讀器、切到筆記分頁。

| 命令 | 文章從哪裡來 | 寫入什麼 | 是否需要 Agent |
| --- | --- | --- | --- |
| 抓取原文全文 | 筆記 Properties 的原文網址 | 取代已辨識原文區塊；沒有則附加文末 | 否 |
| 產生 AI 摘要 | 優先採可辨識全文；找不到或空白時背景抓取 | 摘要與 tags，背景抓到的全文不附加 | 是 |
| 抓取全文並摘要 | 從原文網址重新抓取 | 全文、摘要與 tags；任一步失敗不寫入部分結果 | 是 |

三個命令不會改動訂閱閱讀狀態或文章快取。閱讀器的 `s` 仍只保存 feed 提供的內容，不會呼叫 AI。因此來源只有短摘要時，應在保存後用上述命令補充。

## 第一次設定本機 Agent

插件使用電腦上已安裝的 CLI，沿用其登入與模型設定。內建提供 Codex、Claude Code、OpenCode、pi，也可加入自訂 CLI；插件本身不負責安裝、登入或提供模型服務。

1. 先在終端機確認所選 CLI 已安裝、已登入且能正常使用模型。
2. 開啟「設定 → Vault Feed Reader → 文章全文與 AI 摘要」，找到「本機 Agent」。
3. 查看偵測結果。未偵測到時，在「執行檔名稱或絕對路徑」填入實際執行檔路徑；此欄只放執行檔，不放整串命令。
4. 將要使用的 Agent 設為預設，按「套用本機設定」。若改過路徑或參數，再按「重新偵測已儲存設定」。
5. 按該 Agent 的「測試」，確認目前 CLI、登入與輸出協定可用，再用一篇筆記試跑。

**偵測成功只代表找到執行檔。**「測試」會使用不含筆記內容的測試文字呼叫真實模型，可能消耗額度。沒有實際通過測試前，不應把「已偵測」視為摘要可用。

一般使用先保留內建參數。自訂參數欄是完整啟動參數，不是附加選項；刪掉非互動模式或輸出格式參數可能使 CLI 等待輸入，或使插件無法解析回應。參數不經 shell 執行，不可使用管線、重新導向或 shell 變數展開。

更換模型應調整所用 CLI 的設定，或使用其支援的完整參數；插件沒有獨立模型選單。不同 CLI 版本的可用參數需依該工具文件確認，本文不提供未實測的版本通用指令。

## 原文網址與全文辨識

在「文章全文與 AI 摘要」設定中，「原文網址欄位」預設依序為：

```text
feed_reader_url, source, url
```

這些是筆記 Properties 的欄位名稱，值必須是有效 HTTP(S) 網址。Feed 保存筆記通常已有 `feed_reader_url`；Web Clipper 常使用 `source`。若不同欄位有多個不同網址，插件會請你選擇。

**網址存在不代表筆記已包含全文。**「產生 AI 摘要」依全文辨識結果決定使用現有文字或背景取文。預設標題規則為「原文」「全文」「Article」；例如：

```markdown
## 原文
這裡是文章正文。

## 我的筆記
這裡是自己的心得。
```

標題區塊到下一個同級或更高級標題結束，上例的「我的筆記」不會算進原文。子標題仍屬於該區塊。規則由上到下檢查，第一個符合者優先；多個候選區塊會提示選擇。請將真實的全文區塊設為規則，不要將只有短摘錄的 feed 內容誤認為完整原文。

變更網址欄位、規則、附加全文標題或摘要提示詞後，按「套用文章設定」。這與「套用本機設定」是兩組不同的保存操作。

## 搭配 Web Clipper：直接摘要現有剪藏

假設剪藏筆記已包含完整正文，但沒有「原文」之類的區塊標題，可使用 Properties 條件辨識整份正文。以下為自行設定的範例，不是所有 Web Clipper 模板的預設值：

```yaml
---
source: https://example.com/article
type: clipping
---
```

設定步驟如下：

1. 在剪藏模板或現有筆記加入 `type: clipping`，並確認正文確實是要摘要的文章。
2. 在插件設定新增「整份正文」規則，Properties 欄位填 `type`、符合值填 `clipping`。
3. 若要讓此規則優先，移到其他會匹配的標題規則之前，按「套用文章設定」。
4. 開啟該筆記，執行「產生 AI 摘要」。插件會使用正文，排除 Properties 與已存在的 AI 摘要。

整份正文規則也會把正文裡的個人心得視為輸入；希望只摘要文章時，改用獨立原文標題區塊。這個規則只指定摘要輸入範圍，不會授權插件用抓到的全文取代整份筆記；另外執行抓取命令時，沒有獨立原文區塊就附加於文末。

## 自訂摘要風格與標籤

預設摘要為台灣常用繁體中文的一段概述，加上 3–5 個重點。可以在「摘要提示詞」改成自己的閱讀目的，例如：

```text
請用台灣常用繁體中文整理這篇文章。
先用兩句話說明核心主張，再列出 3–5 個重點。
最後補一段「值得追問」，只指出原文未交代的問題。
保留關鍵數字與技術名稱，不把推測寫成既定事實。
```

設定後按「套用文章設定」。介面切換成英文或繁體中文不會改寫這段提示詞，也不會自動翻譯既有摘要。

同一次摘要請求會要求模型回傳 3–5 個主題標籤，合併到 frontmatter 的 `tags` YAML 清單。原有標籤保留，忽略大小寫去除重複；沒有 frontmatter 時會新增。單獨抓取全文不產生 tags。

重跑摘要會替換摘要區塊，但不清除之前已合併的標籤。若不想保留某些舊標籤，需自行整理 Properties。模型輸出格式無效，或原有 `tags` 不是文字／文字清單時，整次不寫入摘要和標籤。

## 結果放在哪裡？重跑會改什麼？

新摘要放在 Properties 後、原內容前的「AI 摘要」區塊；新全文預設放在文末「原文」區塊。插件以隱藏 HTML 註解標記管理區塊，也能辨識設定的原文標題。

重新擷取會替換被辨識的原文區塊，包含你在那個區塊裡的修改；重跑摘要也會替換舊摘要。因此心得與個人註解適合放在獨立區塊。其餘正文與非目標 Properties 會保留，另依命令合併 tags、維護本插件保存筆記的日期。

工作在背景執行，通知可按「取消」。同一篇只允許一項工作，切換分頁仍以起始筆記為目的地。等待期間如果改過筆記，會顯示結果供複製、取消或明確取代，不會直接覆蓋新修改。已開筆記沿用編輯器 undo 與 Obsidian 自動儲存。

## 常見問題

| 情況 | 檢查方式 |
| --- | --- |
| 找不到原文網址 | 確認設定的欄位存在，且值是有效 HTTP(S) URL |
| 明明剪藏了全文，卻重新抓網頁 | 確認有匹配的標題或整份正文規則，只有 `source` 不夠 |
| 終端機可用，插件未偵測到 | 填絕對執行檔路徑，套用後重新偵測；Windows `.cmd` shim 不能直接啟動 |
| Agent 執行失敗或無回應 | 檢查 CLI 登入、額度與非互動參數；摘要逾時為 120 秒 |
| JSON 或 tags 格式錯誤 | 保留內建輸出參數，檢查既有 tags 型別，重試；失敗不部分寫入 |
| 原文抓不到或內容不完整 | 網頁需公開 HTML；不處理登入、JS 動態內容或付費牆，取文逾時為 30 秒 |

取文成功代表擷取到可讀內容，無法保證網站提供了完整文章；模型摘要仍應對照原文核對。

## 設定保存位置與資料傳送

提示詞、網址欄位與全文規則存在插件設定。Agent 路徑、完整參數、預設選擇與偵測結果存在此裝置、此 vault 的 localStorage；換電腦後需重新檢查，不會只靠複製筆記就恢復 CLI 環境。

「本機 Agent」指本機啟動 CLI，CLI 可以連線到雲端模型；選定的文章文字會交給該 CLI。插件不提供模型服務，需依所用工具的設定與服務額度使用。不要將本機執行誤認為離線推論。

## 自訂 CLI（進階）

在本機 Agent 區新增自訂 CLI，設定執行檔與參數、設為預設並套用。自訂程式由 stdin 接收提示詞與文章 JSON，stdout 應輸出：

```json
{"summary":"一段 Markdown 摘要","tags":["RSS","Obsidian","知識管理"]}
```

除錯訊息不要混入 stdout。標籤不加 `#`、不含空白，可使用連字號、底線或 `/` 階層；插件會驗證回應後才寫入。一般使用者不需要自行組 JSON，內建流程會要求輸出協定。
